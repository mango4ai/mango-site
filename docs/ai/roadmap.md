# 6. 发散篇：学习路线与延伸方向

前五篇搭起了骨架，这一篇给一张地图：**接下来学什么、按什么顺序学、每个方向解决什么问题。**

## 一条分阶段的学习路线

### 阶段一：会用（1–2 周）

目标是把它变成日常工具，而不是先搞懂原理。

- 把自己的真实工作丢给它：写周报、改文案、解释报错、整理会议纪要。
- 练"把需求说清楚"：给背景、给约束、给输出格式、给一两个示例。
- 养成复核习惯：关键事实自己查一遍，代码自己跑一遍。

### 阶段二：懂原理（1–2 个月）

- 概念层：AI / ML / DL 的关系，监督、无监督、强化学习的区别。
- 模型层：token、上下文、预训练、微调、温度、幻觉。
- 动手层：调一次 API，写一个小脚本批量处理文件，感受 token 和成本。

### 阶段三：做应用（2–3 个月）

- **RAG（检索增强生成）**：把你的文档切成块、存进向量库，提问时先检索相关片段再让模型回答。这是解决"模型不知道你的私有知识"和降低幻觉的主力方案。
- **提示词工程**：把重复的提示词固化成模板，做输入输出的结构化约束（JSON Schema 等）。
- **工作流编排**：把多步任务串成流水线，每步可单独测试与重试。
- **Agent 初探**：给它工具，从只读工具（搜索、查库）开始，写操作最后再放开。

### 阶段四：深入与取舍（长期）

- **微调 vs RAG**：知识更新频繁用 RAG；要改变模型的语气、格式或领域风格才考虑微调。先试提示词，再试 RAG，微调放最后——它是成本最高、收益最难验证的一步。
- **评测**：自己攒几十条真实用例当测试集，每次改提示词/模型都跑一遍。没有评测，所有优化都是玄学。
- **成本与延迟**：缓存、批处理、小模型路由（简单问题走便宜模型）是降本的三板斧。

## 术语速查表

| 名词 | 一句话解释 |
| --- | --- |
| RAG | 先检索资料再生成答案，给模型外挂一个可更新的知识库 |
| 向量 / Embedding | 把文本、图像压成一串数字，语义相近的东西在向量空间里也相近 |
| 向量数据库 | 专门存向量并做相似度检索的数据库 |
| 微调 Fine-tuning | 用领域数据继续训练模型，改变它的风格或专精方向 |
| LoRA | 一种便宜的微调方法，只训练很小一部分参数 |
| 量化 Quantization | 用更低精度存储参数，牺牲一点效果换显存和速度 |
| 蒸馏 Distillation | 让小模型学大模型的行为，得到便宜又好用的小模型 |
| 多模态 | 模型同时处理文字、图像、音频、视频 |
| AIGC | AI 生成内容，包括文生图、文生视频、代码生成等 |
| 扩散模型 Diffusion | 主流的图像/视频生成思路：从噪声一步步"擦"出图像 |
| RLHF | 用人类反馈做强化学习，让回答更符合人类偏好 |
| 对齐 Alignment | 让模型的行为符合人的意图与价值观 |
| 越狱 Jailbreak | 绕过模型安全限制的手段，也是安全防护要研究的对象 |
| 评测 Benchmark | 用标准化题目衡量模型能力，注意"刷榜"并不等于实用 |
| 推理模型 | 回答前先展开较长的思考链条，擅长复杂推理，代价是更慢更贵 |

## 值得继续深挖的方向

1. **RAG 工程**：切分策略、混合检索（关键词 + 向量）、重排序、引用溯源——企业落地的第一大头。
2. **Agent 工程**：循环控制、上下文管理、权限边界、可观测性，也就是 Harness 那一层。
3. **提示词与评测**：把模糊需求变成可测量、可回归的用例。
4. **多模态**：图文混合输入、文档解析、截图理解，很多真实场景的入口是图片而非文字。
5. **本地与私有部署**：数据不出网的场景，以及量化、蒸馏带来的成本优化。
6. **AI 安全与合规**：数据脱敏、权限最小化、输出审计、人责归属。
7. **与传统工程结合**：把 AI 塞进已有的 CI、监控、客服、报表系统里，而不是另起炉灶。

## 三条长期有用的原则

- **先问流程，再问模型**：很多"模型不行"的问题，其实是需求没讲清、流程没设计好。
- **把不确定变成可验证**：让它给出引用的原文、可执行的命令、可复现的结果，而不是一句结论。
- **保留人的判断权**：AI 负责提速和兜底，决策与责任仍然在人。

## 还不懂的地方

- 这个领域半年一变，具体工具会过时；上面这些**分层结构和取舍原则**相对耐用。
- 学得最快的办法仍然是用它解决自己的真问题，然后写下踩坑——本站的 `docs/ai/` 就是干这个的。
