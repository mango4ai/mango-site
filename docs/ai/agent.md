# 四、Agent

这是当前 AI 领域最热、也最容易被说玄乎的词。先把它从神坛上拉下来：

**Agent（智能体）**：把大模型放进一个循环里，**让它自己决定"下一步做什么、调哪个工具"，执行后看结果，再决定再下一步**，直到任务完成或放弃。

一句话定义：**Agent = 大模型 + 工具 + 循环 + 目标。**

## 和聊天机器人有什么不同

| | 聊天机器人 | Agent |
| --- | --- | --- |
| 输出 | 一段文字 | 一段文字 **+ 一系列真实发生的动作** |
| 谁能改变外部世界 | 不能，只有你在改 | 能：读写文件、跑命令、发请求 |
| 一轮对话做什么 | 问一句答一句 | 一个目标，自己拆成很多步 |
| 失败了怎么办 | 只能你再来问一遍 | 自己看到报错，换个办法重试 |
| 关键区别 | 它只负责"说" | 它开始负责"做" |

**判断标准很朴素：它有没有真的动手改变了什么东西？** 只生成文字的，再 fancy 也只是聊天。

## 核心循环

所有 Agent 都是同一个圈，不停地转：

```
1. 感知：现在是什么情况？（任务、已有上下文、上一步的结果）
2. 思考：下一步该干什么？调哪个工具、传什么参数？
3. 行动：真的去执行（读文件 / 跑命令 / 调接口）
4. 观察：拿到了什么？成功还是报错？
       ↓
   目标达成了吗？没有 → 回到第 1 步
```

这个圈也叫 **ReAct 模式**（Reason + Act）。理解它就理解了 Agent 的全部骨架。

### 一个具体例子

任务："把这个项目里所有 TODO 注释整理成一个清单。"

1. 思考：得先找到代码在哪 → 行动：列出项目目录结构
2. 观察：看到 `src/`、`docs/`……
3. 思考：去源码里搜 TODO → 行动：搜索 `TODO`
4. 观察：命中 12 处，其中 2 处在测试文件
5. 思考：用户大概不想要测试里的 → 行动：只保留源码的 10 处，读取上下文
6. 观察：内容齐了 → 思考：可以输出了 → 行动：写出清单文件
7. 观察：写成功 → 判断完成，结束

注意第 5 步：**它在中途自己做了个判断**。这个"自己决定"的能力，就是 Agent 和脚本的分界线——脚本的步骤是人写死的，Agent 的步骤是它当场想的。

## Agent 由什么组成

- **大脑**：大模型，负责规划和决策。
- **工具（Tools）**：它能调用的能力——读写文件、执行 shell、搜索网页、查数据库、调第三方 API。
- **记忆 / 上下文**：对话历史、已读过的文件内容、之前的失败尝试。
- **终止条件**：什么时候算完、最多转多少圈、预算上限——**没有这个，它会一直转下去。**
- **外壳（Harness）**：把这些装配起来并管住它的那一层。这是下一页 [Harness](/ai/harness) 的主题。

## 为什么它现在才火

因为三件事同时成熟了：

1. 模型的**指令跟随**和**规划能力**终于够用（以前它连"按这个 JSON 格式输出"都做不稳）。
2. **工具调用（Function Calling / Tool Use）** 成了模型的原生能力，模型可以明确地说"我要调这个工具，参数是这些"。
3. **上下文窗口**足够长，能装下多步执行的中间结果。

## 它的问题也很真实

- **会跑偏**：目标说得太模糊，它可能干一堆你不想要的事，还觉得自己在帮忙。
- **错误会累积**：第一步判断错了，后面全错，而且它不知道自己错了。
- **成本不可控**：每一步都要重新发送整个上下文，多轮循环烧 token 很快。
- **有安全风险**：它有能力执行命令、删文件、发请求，就必须有权限边界。**不要给 Agent 超出任务需要的权限。**
- **不好评估**：同一个任务这次成功下次失败，很难像测函数一样测它。

### 用得好的几条经验

- **把目标写具体**，包括"什么算完成"和"哪些不要动"。
- **给只读的探索阶段**：先让它只搜索、只读取，确认方案后再允许写入。
- **限制步数和预算**，别让它自由发挥到天亮。
- **关键动作要求人工确认**，尤其是删除、提交、发布。
- **让它留下痕迹**：记录它做了什么，事后能复盘。
