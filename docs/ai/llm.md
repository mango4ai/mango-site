# 3. 大模型篇：LLM 是怎么工作的

**LLM（Large Language Model，大语言模型）**：在海量文本上训练出来的超大规模神经网络，核心能力只有一件——**给定前面的内容，预测下一个最可能的 token**。对话、写代码、做翻译、做推理，都是这一个能力被"放大"之后的表现。

## 它是怎么被造出来的

```text
预训练（读遍互联网，学会语言与世界知识）
  → 后训练 / 微调（学会听指令、按格式回答）
  → 对齐（RLHF 等，学会符合人类偏好、拒绝有害请求）
  → 部署推理（用户开始提问）
```

- **预训练**：把几千亿到几万亿 token 的文本喂进去，反复做"猜下一个词"。这一步吃掉了 99% 的算力和钱，产出的叫**基座模型**（base model），它只会续写，不会好好回答你的问题。
- **后训练 / 微调**：用人工写的高质量问答对教它"怎么当一个助手"，也用来注入领域知识（法律、医疗、代码）。
- **对齐**：让人给回答打分，用强化学习把模型拉向人类偏好。ChatGPT 之所以"像人"而不是"像文档续写机"，功劳主要在这步。
- **推理**：模型固定下来对外服务，这一步不再学新东西——**它不会因为你跟它聊过就记住你**（除非产品层面做了记忆功能）。

## 用的时候会撞上的词

- **上下文窗口 Context Window**：模型一次能"看到"的 token 上限，包含你的提问 + 它的回答 + 历史对话 + 你贴的资料。超了就会被截断，前面的内容直接失效。
- **幻觉 Hallucination**：一本正经地编造事实、文献、法条。它不是"撒谎"，而是模型在概率上觉得这样接下去最顺。**凡是关键事实，必须自己复核。**
- **温度 Temperature**：控制随机性。低温更确定、更保守（适合代码、抽取、格式化）；高温更发散、更有创意（适合头脑风暴）。
- **System Prompt（系统提示词）**：在对话开始前设定角色、规则、输出格式，优先级高于用户后续指令。
- **Few-shot（少样本示例）**：在提问里给两三个"输入→输出"的例子，比用自然语言描述需求更管用。
- **Token 与计费**：输入输出都算钱。中文通常一个字约 1–2 个 token，长对话成本主要花在反复重发的历史上下文上。
- **知识截止**：训练数据有时间点，之后的事件它不知道。需要最新信息时得给它检索工具或贴原文。

## 能力边界：它擅长什么、不擅长什么

| 擅长 | 不擅长 |
| --- | --- |
| 改写、润色、总结、翻译 | 精确计算与大数运算 |
| 按格式抽取与结构化 | 需要实时数据的问题（无工具时） |
| 代码草稿、解释报错 | 保证事实准确（会幻觉） |
| 头脑风暴、发散思路 | 需要长期记忆与稳定状态的任务 |
| 把模糊需求变成步骤清单 | 承担责任与判断后果 |

::: tip 一个实用的心智模型
把 LLM 当成**一个读过海量书、反应极快、但没有生活经验也没有责任感的实习生**：给它清晰的任务、足够的背景材料、明确的验收标准，它产出惊人；让它自己猜需求，它就会自信地胡说。
:::

## 怎么挑模型（不谈具体品牌）

1. **任务难度**：简单改写用小模型，便宜且快；复杂推理、长文综合用大模型。
2. **上下文长度**：要塞进长文档，先看窗口大小，再看长上下文下的实际表现（很多模型窗口标称很大，尾部会"走神"）。
3. **部署形态**：云端 API 省事但数据出网；本地/私有部署可控但要自己备显卡。
4. **是否要工具/多模态**：需要联网、调接口、看图，确认模型支持函数调用或视觉输入。

## 还不懂的地方

- 为什么加参数、加数据后能力会"台阶式"跃升，没有统一的理论解释。
- 幻觉能不能被彻底消除？目前只能靠检索增强（RAG）与流程约束降到可接受水平。
