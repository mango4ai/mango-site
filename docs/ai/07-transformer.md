# Transformer 与注意力机制

前六篇都是"怎么用、怎么理解行为"，这一篇往下钻一层：**支撑大模型的那个结构到底是什么。**

不打算推公式。目标是读完能对"注意力""多头""上下文""向量"这些词有具体的画面，而不是只记住名字。

## 先说它解决了什么问题

在 Transformer 之前，处理序列（一句话、一段文字）的主流结构是 RNN / LSTM：

```text
读到第 1 个词 → 更新记忆 → 读到第 2 个词 → 更新记忆 → ……
```

两个硬伤：

1. **必须串行**：算完前一个才能算后一个，几万张卡也只能排队干等，规模上不去。
2. **长距离遗忘**：信息要一步步传下去，传到第 50 个词时，第 1 个词的影响已经淡得几乎没了。所以它写不好长文、抓不住开头的约束。

Transformer 的解法很直接：**别再一步步传了，让每个位置直接去看所有位置。** 这样既能并行算，也不会因为距离远而丢失。

## 注意力：一句话 + 一个类比

一句话：**对每个位置，给所有位置打一个"相关度"分数，然后按分数加权求和，得到这个位置的新表示。**

类比成查资料：

- 你手上的问题 = **Query（Q，查询）**
- 每条资料的标题/索引 = **Key（K，键）**
- 资料本身的内容 = **Value（V，值）**

过程是：拿 Q 去和所有 K 比对，算出每条资料"跟我的问题有多相关"（分数），再用这些分数当权重，把所有 V 加权平均起来当成答案。**分数高的资料贡献多，分数低的几乎不贡献。**

放到句子里，"它"这个词会去和前面所有词算相关度，发现"那只猫"分数最高，于是"它"的表示里就混进了"猫"的信息——**这就是它理解了指代**。

### 自注意力

Q、K、V 全都来自同一句话本身，这叫**自注意力（Self-Attention）**：句子自己和自己算相关度，互相更新表示。

### 多头注意力

一组 Q/K/V 只能从一种角度找关联。所以同时开很多组（比如 32 个"头"），有的头专门盯语法主谓，有的头盯指代，有的头盯相邻词。最后把各头的结果拼起来。

**这就是"多头"：多路并行地从不同角度找关系。**

## Transformer 长什么样

原始论文是编码器 - 解码器结构（为机器翻译设计）：

```text
编码器：把输入读进去，每层 = 多头自注意力 + 前馈网络
解码器：边生成边看编码结果
```

但今天的大语言模型几乎全是 **decoder-only**：只留解码器那一半，不断"根据前面的内容预测下一个 token"。你现在用的所有对话模型都是这个形态。

每一层大致是：

```text
多头自注意力  →  前馈网络（FFN）  →  残差连接 + 归一化
```

然后把这样的层叠几十上百层。**注意力负责"信息和信息之间怎么流动"，前馈网络负责"每个位置自己怎么加工"。**

## 位置编码：并行带来的新问题

既然每个位置是直接看全局的，模型就不像 RNN 那样天然知道顺序了——"猫追狗"和"狗追猫"在它眼里会是一袋子同样的词。

所以要在输入里**额外加一段表示位置的信息**（位置编码），让模型知道"你在第几位"。现在常见的是 RoPE 这类旋转位置编码，它编码的是相对距离，因此外推到更长上下文时表现更稳。

这也解释了一个现象：**模型对"最近的内容"通常更敏感**，离得越远，位置关系越模糊。

## Embedding：把语义变成坐标

模型不认识"字"，只认识数字。第一步是把每个 token 映射成一个高维向量（比如几千维），这一步叫 **Embedding（嵌入）**。

关键性质：**意思相近的东西，向量在空间里也靠近。** 于是"语义"变成了可以算的几何问题：

- 相似 = 两个向量夹角小（余弦相似度高）。
- 类比能成立："国王 - 男人 + 女人 ≈ 女王"这种向量运算在 embedding 空间里真的成立。

RAG 就是在这一层工作的：把文档切片 → 每片算成向量 → 存进向量库 → 提问时把问题也算成向量 → 找最相近的几片塞进上下文。**检索靠的是向量距离，不是关键词匹配**，所以能命中"说法不同但意思一样"的内容。

## 为什么是它赢了

| 特性 | 带来的结果 |
| --- | --- |
| 全局直连 | 长距离依赖不再衰减，长文本可用 |
| 高度并行 | 训练能吃满成千上万张 GPU，规模第一次成为可堆的变量 |
| 结构统一、好堆叠 | 加层数、加宽度、加数据就能稳定变强（缩放定律） |

最后一条最关键：**别的架构很难靠"加大"持续变强，Transformer 可以。** 于是算力和数据一旦堆上去，能力就台阶式地涌现出来（见 [03 · 大模型](/ai/03-llm) 的"涌现"）。

## 三个常见误解

1. **"注意力 = 模型在关注哪里"**——不准确。注意力权重是相关度打分，不等于人类的"注意"，也不能当成解释模型为什么这么答的依据。
2. **"它理解了"**——它学到的是海量文本里的统计结构。很好用，但不等于有意图或有世界模型，这也是幻觉的根源。
3. **"注意力算得越多越聪明"**——注意力的开销是**序列长度的平方级**：上下文翻一倍，算量翻约四倍。这是长上下文昂贵、需要各种稀疏/压缩注意力的根本原因。

## 顺带解释两个工程现象

- **为什么输入比输出便宜**：输入可以并行一次算完所有位置的注意力；输出必须一个 token 一个 token 地串行生成。
- **为什么有 KV Cache**：生成时前面算过的 K、V 可以缓存复用，不用每步重算——省的是算力，但**缓存本身要占显存**，所以长上下文会"吃内存"。
