# 发散

前面五篇是"知道是什么"，这一篇是"接下来往哪走"。

## 一条务实的路线

不用按顺序全啃完，**动手优先级永远高于看教程**。

### 阶段一：会用（1 ~ 2 周）

- 把日常问题真的丢给模型：改文案、解释报错、写正则、总结长文。
- 练提示词：给背景、给约束、给示例输出。**对比两次不同写法的差异**，这比看十篇技巧文有用。
- 养成一个习惯：**关键结论自己核实一遍**。

### 阶段二：知道边界在哪（2 ~ 4 周）

- 搞清 token、上下文窗口、temperature 这些参数实际影响什么（见 [03 · 大模型](/ai/03-llm)）。
- 亲手制造一次幻觉：问一个你知道答案的冷门问题，看它怎么编。
- 用 API 跑通一次调用，把价格、延迟、返回结构摸清楚。

### 阶段三：接到自己的东西上（1 ~ 2 月）

- 做一次最小 RAG：把自己的文档切片、检索、塞进上下文回答。
- 写一个只有 2 ~ 3 个工具的小 agent，跑通"观察 - 行动 - 观察"的回环。
- 试装一个 MCP server，再试着自己写一个。

### 阶段四：工程化（持续）

- 关注评测：怎么量化"变好了"，而不是凭感觉。
- 关注成本与延迟：缓存、批处理、模型分级（简单任务用小模型）。
- 关注失败模式：日志、可回滚、人工确认点。

## 新手最容易踩的坑

1. **把提示词当咒语背**——真正起作用的是"信息有没有给全"，不是"措辞够不够玄"。
2. **一上来就微调**——九成问题靠更好的上下文就解决了。
3. **不看 token**——上下文超了不知道，价格算不清，出问题时无从下手。
4. **信任输出**——它会编法条、编论文、编 API。凡是要落地执行的，必须核实。
5. **工具堆满**——工具超过十几个，模型选择能力会明显下降。
6. **不给 Agent 设边界**——破坏性操作一定要人工确认，一定要能回滚。
7. **只追新模型名**——换模型带来的提升，常常不如把上下文和工具描述改好。

## 名词速查表

| 名词 | 一句话 |
| --- | --- |
| AI / ML / DL | 层层包含：人工智能 ⊃ 机器学习 ⊃ 深度学习 |
| LLM | 大语言模型，本质是预测下一个 token |
| Token | 子词单元，上下文和计费都按它算 |
| 上下文窗口 | 一次能塞进去的 token 上限 |
| 预训练 / 后训练 | 学语言规律 / 学按指令说话 |
| RLHF | 用人类偏好数据对齐模型行为 |
| 涌现 | 规模过阈值后突然出现的新能力 |
| 幻觉 | 流畅但无依据的编造 |
| 微调 | 在你的数据上继续改模型参数 |
| RAG | 先检索资料，再让模型基于资料回答 |
| Function Calling | 模型输出"我要调用哪个工具、参数是什么" |
| Agent | 模型 + 工具 + 循环，为目标自主执行 |
| Harness | 模型外面那套驱动系统：上下文、工具、权限、日志 |
| MCP | 工具与数据源的统一接入协议 |
| Skills | 打包好的流程与脚本，按需加载 |
| Sub-agent | 带独立上下文的子任务执行者 |
| Temperature | 输出随机性的旋钮 |
| 多模态 | 能同时处理文字、图像、音频等 |
| 推理模型 | 生成答案前先展开更长思考过程的模型 |
