# 大模型 LLM 到底在做什么

## 一句话本质

**给定前面的内容，预测下一个最可能的 token（词元）。** 然后把预测出来的 token 接回输入，再预测下一个，如此循环。

所有看似神奇的能力——写诗、debug、做翻译——都是这个机制在足够大的规模上涌现出来的。

理解了这一点，很多反常现象就说得通了：

- 它为什么会算错 `17 × 24`？它从来没在计算，只是在猜"这个算式后面通常跟什么数字"。
- 它为什么会编造论文？它在生成"看起来最像答案的文本"，而不是检索。
- 为什么让它"一步步想"会变强？因为每生成一个中间步骤，就多给了它一次预测依据。

## Token：计费、上下文和"记性差"的根源

Token 不是字也不是词，而是**子词单元**。英文里一个常见词通常是一个 token，生僻词会被切成几块；中文一般一个字 1 个 token 左右（不同分词器差异不小）。

为什么重要：

- **上下文窗口**按 token 计数，不是按字。128K 上下文，中文大约能装十万字上下。
- 窗口满了以后最早的内容会被丢掉或压缩，这就是"聊久了它把前面的需求忘了"。
- 价格和速度也按 token 算，输入输出通常分开计价。

## 它是怎么被训练出来的

```text
预训练 → 后训练 → 对齐
```

1. **预训练**：在海量文本上做"预测下一个 token"。学到的主要是语言规律与世界知识，这一步烧掉绝大部分算力。
2. **后训练（SFT）**：用高质量的"指令 - 回答"示范数据，教会它**按指令说话**，而不是续写网页。
3. **对齐（RLHF / DPO 等）**：用人类偏好数据继续调，让它更有用、更安全、更愿意承认不知道。

所以"它很聪明"来自预训练，"它听话且好用"来自后训练和对齐。

## 三个必须知道的特性

### 涌现

规模（参数、数据、算力）跨过某个阈值后，会突然出现一些没被专门训练的能力，比如多步推理、代码补全、少样本学习。**不是线性增长的，是台阶式的。**

### 幻觉

模型不知道自己不知道。它会用最流畅的方式补全一个它其实没有依据的答案。

应对办法（按成本从低到高）：

- 要求给出来源，并**自己去核实**。
- 提供资料让它只基于资料回答（RAG）。
- 降低 temperature，减少随机性。
- 关键结论让另一个模型或另一次对话复核。

### 概率性输出

同样的输入可能给出不同结果。做产品时要么接受这个抖动，要么在流程里加校验。**把 LLM 当成"模糊但有创造力的组件"，别当成数据库。**

## 想让它做特定领域的事，三条路

| 方案 | 做什么 | 什么时候用 |
| --- | --- | --- |
| 提示词 / 上下文工程 | 改输入，不改模型 | 首选，成本最低，见效最快 |
| RAG（检索增强） | 先检索你的资料，塞进上下文再回答 | 知识经常更新、需要可追溯来源 |
| 微调 | 改模型参数 | 要固定风格 / 格式 / 特定任务，且已有足量高质量数据 |

经验法则：**先提示词，再 RAG，最后才考虑微调。** 大多数"模型不够好"的问题，其实是上下文没给够。

## 几个常见参数

- **temperature**：随机性。要严谨输出就调低（0 ~ 0.3），要创意就调高（0.7 ~ 1）。
- **top_p**：另一个控制随机性的旋钮，和 temperature 一般只调一个。
- **max_tokens**：本次最多生成多少，防止跑飞。
- **system prompt**：放在最前面、优先级最高的行为指令，用于定义角色、边界和风格。

## 还没弄懂的地方

- "预测下一个 token"怎么就能推出多步推理？机制上到底发生了什么，见过几种互相打架的解释，还没能判断哪种更可信。
- 思维链为什么有效，"每步都多给一次预测依据"这个解释说得通，但推理模型内部那段思考过程具体在做什么，只能先当黑盒。
- 幻觉到底能不能被彻底消除，还是概率模型的固有代价、只能被压低？如果答案是后者，所有严肃的 LLM 系统架构都得围绕这个假设来设计——这直接决定该信它几分。
