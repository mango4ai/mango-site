# 4. 发散：边界、误区与下一步学什么

前面三页是知识，这一页是判断力——**知道它能做什么、不能做什么，比会调 API 更重要。**

## 一、它擅长什么，不擅长什么

| 擅长 | 不擅长 |
| --- | --- |
| 把模糊的想法整理成结构 | 需要精确数值的计算（它是在"生成"，不是在"算"） |
| 大段内容的总结、改写、翻译 | 对你私有信息的了解（没接进去它就没见过） |
| 生成样板代码和常规套路 | 判断自己不知道什么（会一本正经地编） |
| 充当"第一稿生成器"，给你一个起点 | 承担后果。错了它不负责，负责的是你 |
| 解释概念、帮你入门陌生领域 | 长期记忆（上下文一关就忘，除非外部存储） |

::: tip 一个好用的心智模型
把它当成**一个读过几乎所有书、但没上过班的实习生**：知识面极广、手脚很快、非常听话，但没常识、不担责、会编造。

你要做的是**派活、审查、给反馈**，而不是把决定权交出去。
:::

## 二、新手最容易踩的五个坑

1. **把"说得像"当成"说得对"**
   幻觉是结构性的，不是 bug。凡是事实、数字、引用、法律与医疗相关结论，一律自己核一遍。

2. **上下文塞太满**
   东西不是越多越好。无关内容会稀释注意力，还花钱。给模型的是**刚好够用的最小上下文**。

3. **要求说得太含糊**
   "帮我写得更好一点"没有可执行的判断标准。给角色、给背景、给示例、给输出格式，效果差一倍以上。

4. **一次性托付整个大任务**
   拆成小步、每步验证，比扔一个大需求过去然后祈祷要可靠得多。出错时也好定位。

5. **忽略权限边界**
   能读你的文件、能跑命令的 Agent，潜力大、风险也大。哪些目录可写、哪些命令要确认，值得花五分钟配好。

## 三、几个值得自己去想的问题

没有标准答案，想清楚这些比多背几个名词有用：

- **"理解"和"生成得像理解"有区别吗？** 从外部表现上，我们其实很难区分。
- **一个只会预测下一个 token 的系统，为什么展现出推理能力？** 规模到一定程度后涌现的能力，是"真的会"还是"见得太多"？
- **效率提升之后呢？** 当写初稿、写代码的时间成本趋近于零，什么会变得更值钱？（大概率是：判断该做什么、以及如何验证结果对不对。）
- **"会用 AI"会不会变成新的分水岭？** 会用的人和不用的差距在拉大，但"会用"本身也在快速贬值。
- **我们该怎么处理它生成的内容？** 版权、真实性、责任归属，目前都还在模糊地带。

## 四、下一步可以学什么

按"先建立手感，再补原理"的顺序：

| 阶段 | 做什么 | 目标 |
| --- | --- | --- |
| 1. 用起来 | 把日常重复的文字工作交给它：总结、改写、翻译、起标题 | 建立"它能到什么程度"的直觉 |
| 2. 练提示词 | 同一个任务写三版 prompt 对比效果，记录哪一版好、为什么 | 学会把需求说清楚 |
| 3. 碰工具 | 用一个带文件/命令能力的 Agent 做件真事（比如整理一批文件） | 理解 Agent 和 Harness 的作用 |
| 4. 补原理 | 回头看 Transformer、注意力机制、训练流程 | 从"会用"到"知道为什么" |
| 5. 做小项目 | 搭一个自己的 RAG：把你的笔记喂进去，问它问题 | 把前面几层串起来 |

::: tip 学习建议
不要从数学和论文开始。先用起来、攒出问题，再带着问题回去补原理——逆着"学院派"的顺序学，对大多数人是更快的路。
:::

## 五、一些值得关注的延伸方向

- **推理模型**：让模型在回答前先"想一会儿"，用更多算力换更可靠的结果
- **模型小型化**：小模型跑在本地设备上，成本、隐私、延迟都更好
- **多模态**：文字、图像、语音、视频打通，输入输出不再单一
- **Agent 协作**：多个专职 Agent 分工配合，而不是一个模型干所有事
- **记忆与个性化**：跨会话记住你的偏好和背景
- **AI 与工程流程的结合**：代码评审、测试生成、故障定位这些环节正在被重塑
- **安全与对齐**：越强大、越自主的系统，越需要可靠的边界控制

## 六、回到起点

这个板块的四页，是为了搭一个能继续往上长的架子：

```text
1. 概念     —— 这些词在说什么
2. 发展     —— 它们从哪来、为什么是现在
3. 大模型栈 —— 现在这套东西是怎么拼起来的
4. 发散     —— 边界在哪、接下来往哪走
```

接下来值得做的，是把每一页里的"听说过的词"变成"亲手做过一遍的事"。笔记就写在这个板块里。
